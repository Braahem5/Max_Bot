# MAX Бот-помощник по льготам

Бот-помощник по подбору льгот и мер поддержки для мессенджера MAX.
Трек «Забота о людях», Хакатон MAX 2026. Пользователь кнопками выбирает
категорию (студент / пенсионер / многодетная семья / инвалидность / ищу
работу) и регион, бот показывает список подходящих льгот с описанием,
источником, порядком оформления и списком необходимых документов.
Никакого free-text-парсинга: только инлайн-кнопки. Интеграции с
Госуслугами нет, база льгот своя, статичная демо-версия.

Отдельно от базы льгот бот работает с реальным MAX API: при старте
подтверждает у платформы, что токен рабочий (`bot.get_me()`; при
неверном токене бот завершается с понятной ошибкой в логе, при временном
сбое сети или MAX повторяет запуск до 5 раз) и персонализирует
приветствие именем из профиля пользователя, уже присутствующим во
входящем событии.

## Для кого и зачем

**Пользователь:** родитель в многодетной семье (трое и более детей), который
хочет понять, на какие федеральные и региональные меры поддержки он вправе
рассчитывать и как их оформить.

**Проблема:** сведения о льготах разбросаны по разным ведомствам (СФР, органы
соцзащиты, региональные порталы) и зависят от региона. Человеку приходится
самому искать и сопоставлять условия, из-за чего часть положенного остаётся
неоформленной или оформляется с опозданием, после лишних походов по
инстанциям.

**Что делает бот:** за три нажатия (категория, регион, льгота) показывает
подходящие меры поддержки и карточку с описанием, источником (закон и
ведомство), порядком оформления и списком документов. Бот отвечает на
вопрос «что мне положено и что нести», ещё до похода в ведомство. Заявления
он не подаёт и статус заявлений не отслеживает: для этого есть Госуслуги и
официальный бот СФР в MAX.

**Основной сценарий:** `/start` → «Многодетная семья» → регион → карточка
льготы → «Назад к списку» или «Начать заново». Остальные категории
(студент, пенсионер, человек с инвалидностью, ищу работу) лежат в той же
базе и показывают, как решение масштабируется (см. раздел
«Масштабирование»).

## Требования к окружению
* **Python 3.10** или выше

## Запуск бота-помощника по льготам (long polling, без туннеля)

MAX-библиотека `maxapi` в режиме long polling сама опрашивает сервер.
Публичный HTTPS-адрес и туннель не нужны, доверенный порт открывать не
требуется.

```bash
git clone <URL_ЭТОГО_РЕПОЗИТОРИЯ>
cd Max_Bot

python -m venv venv
source venv/bin/activate  # Windows: .\venv\Scripts\Activate.ps1
pip install -r requirements.txt

export MAX_BOT_TOKEN="ваш-токен-от-MasterBot"  # Windows: $env:MAX_BOT_TOKEN="..."
python benefits_bot.py
```

Вместо `export` можно создать рядом с `benefits_bot.py` файл `.env`
(`cp .env.example .env`) и вписать токен туда: бот подхватывает его сам.
Если токен не задан вообще, бот сразу завершится с сообщением в логе.

Бот стартует и сразу принимает сообщения. Откройте MAX, найдите бота и
отправьте `/start`. Процесс должен оставаться запущенным всё время, пока
бот должен отвечать: ноутбук с активным терминалом либо любой
всегда-включённый хост. Вебхук и туннель для этого не нужны.

## Запуск через Docker

```bash
cp .env.example .env
# впишите в .env свой MAX_BOT_TOKEN

docker compose up --build
```

Токен можно передать и без файла `.env`, через переменную окружения:
`MAX_BOT_TOKEN="..." docker compose up --build`. Если токена нет совсем,
контейнер запустится и сразу напишет в лог, что токен не задан.

Одна команда поднимает единственный компонент решения, сам бот.
Внешних сервисов, базы данных или дополнительных контейнеров нет: вся
база льгот это `data/benefits.json`, встроенный в образ. Сборка образа
занимает меньше минуты (без учёта первой загрузки базового образа
`python:3.12-slim`).

**Порты:** не используются и не публикуются. Бот работает по long
polling (сам опрашивает MAX API исходящими запросами), входящих
подключений к контейнеру нет.

**Переменные окружения:**
- `MAX_BOT_TOKEN` (обязательная): токен бота от MasterBot в MAX.
- `MAX_DELETE_WEBHOOK=1` (необязательная, подходят также `true` и `yes`):
  перед стартом удалить все
  подписки на вебхук для этого токена. Нужна, если этот токен раньше
  использовали с вебхуком: пока подписка есть, MAX не отдаёт обновления
  через polling (в логе будет предупреждение «БОТ ИГНОРИРУЕТ POLLING»). По
  умолчанию выключена, чтобы не отключить другое развёртывание на том же
  токене.

**Остановка и повторный запуск:**
```bash
docker compose down       # остановить
docker compose up --build # запустить заново (учтёт изменения в коде/данных)
```
Состояние диалога не персистентно, и это осознанное решение: каждый шаг
диалога кодируется в payload нажатой кнопки на стороне MAX, поэтому
перезапуск контейнера не обрывает и не путает уже открытые у
пользователей диалоги.

**Известные ограничения:**
- База льгот: статичный демо-набор (21 запись, см. `_meta.disclaimer`
  в `data/benefits.json`), не интеграция с Госуслугами/СФР. Размеры
  выплат и условия нужно перепроверять на дату использования.
- Свободный текст бот не разбирает. Сценарий полностью кнопочный, это
  осознанное продуктовое решение: на любое сообщение, кроме `/start`, бот
  отвечает подсказкой и возвращает кнопки.
- Бот не проверяет право на льготу поимённо (не спрашивает доход и состав
  семьи) и не подаёт заявления. Он показывает, какие меры существуют и что
  подготовить.
- Регионов шесть плюс федеральный уровень. Для остальных регионов бот
  покажет только федеральные меры.
- Работает один экземпляр бота по long polling. Поведение под большой
  нагрузкой в MVP не проверялось.

## Как проверить основной сценарий

Шаги ниже проходят полный путь от `/start` до карточки конкретной
льготы, с примерами того, что бот ответит на каждом шаге. Проверяли на
паре категория/регион «многодетная семья» + «Москва»; с другими
категориями и регионами шаги те же, отличается только список результатов.

**1. Отправьте `/start` (или откройте диалог с ботом впервые).**
Ожидаемый ответ: приветствие с именем из вашего профиля MAX и пять
кнопок-категорий.
```
Привет, Анна! 👋 Я помогу подобрать льготы и меры поддержки, на которые
вы можете претендовать.

Отвечу на пару вопросов кнопками и покажу список того, что вам
положено, с описанием, порядком оформления и списком документов.

Для начала: кто вы?
[Студент] [Пенсионер] [Многодетная семья] [Человек с инвалидностью] [Ищу работу / безработный]
```

**2. Нажмите «Многодетная семья».**
Ожидаемый ответ: подтверждение категории и семь кнопок-регионов.
```
Категория: Многодетная семья

Теперь укажите регион: часть льгот региональные.
[🌍 Федеральные (все регионы)] [Республика Калмыкия] [Москва] [Краснодарский край] [Свердловская область] [Республика Татарстан] [Санкт-Петербург] [⬅ Начать заново]
```

**3. Нажмите «Москва».**
Ожидаемый ответ: три подходящие льготы (две федеральные плюс одна
московская), каждая с кнопкой для подробностей.
```
Категория: Многодетная семья · Регион: Москва

Нашёл 3 подходящие льготы. Нажмите на название, чтобы узнать подробности и как оформить:

• Материнский (семейный) капитал
  728 922 ₽ на первого ребёнка, 963 243 ₽ на второго...

• Единое удостоверение многодетной семьи
  Единый федеральный статус многодетной семьи действует по всей России...

• Социальная карта многодетной семьи Москвы
  Ежемесячные и разовые региональные выплаты многодетным семьям Москвы...

[ℹ️ Материнский (семейный) капитал] [ℹ️ Единое удостоверение многодетной семьи] [ℹ️ Социальная карта многодетной семьи Москвы]
[⬅ Начать заново]
```

**4. Нажмите «Социальная карта многодетной семьи Москвы».**
Ожидаемый ответ: полная карточка льготы с источником, порядком
оформления и списком документов.
```
📌 Социальная карта многодетной семьи Москвы

Помимо федеральных мер, Москва предоставляет многодетным семьям
собственный пакет поддержки: региональные ежемесячные выплаты на детей,
компенсацию за детский сад, бесплатное питание школьникам,
льготный/бесплатный проезд и социальную карту со скидками у партнёров.

📚 Источник:
Постановление Правительства Москвы о мерах социальной поддержки
многодетных семей; портал mos.ru.

✅ Как оформить:
Оформление статуса многодетной семьи и социальной карты: через МФЦ
«Мои документы» или портал mos.ru.

📋 Какие документы понадобятся:
  1. паспорта родителей
  2. свидетельства о рождении всех детей
  3. удостоверение многодетной семьи
  4. документ о регистрации по месту жительства в Москве
  5. заявление в МФЦ «Мои документы» или на mos.ru

🕒 Данные собраны 12.09.2026. Суммы и условия могут измениться: перед
подачей заявления уточните их в органе соцзащиты, СФР или на Госуслугах.

[⬅ Назад к списку] [⬅ Начать заново]
```

**5. Нажмите «⬅ Начать заново».**
Ожидаемый ответ: то же приветствие, что и в шаге 1. Диалог не завис и
не потерял состояние.

**Проверка обработки ошибок:**
- Отправьте боту любой обычный текст (не `/start`). Бот не промолчит:
  ответит, что понимает только кнопки, и снова покажет выбор категории.
  В групповых чатах бот на обычные сообщения не отвечает.
- Если изменить `data/benefits.json` и удалить категорию или регион, пока
  у пользователя на экране старая клавиатура, нажатие такой кнопки не
  уронит бота. Ответ будет: «Этот вариант больше не в базе. Начнём
  заново», с возвратом к экрану категорий.
- Каждое нажатие кнопки бот подтверждает коротким уведомлением
  «Секунду…», чтобы у пользователя не висел индикатор загрузки.

## Состав и архитектура решения

```
Пользователь в MAX
      │  нажатие кнопки или сообщение
      ▼
MAX Bot API ◄── бот сам опрашивает сервер (long polling, входящих портов нет)
      │
      ▼
benefits_bot.py    диалог: хэндлеры, клавиатуры, payload кнопок
      │  find_benefits(категория, регион)
      ▼
benefits_data.py   загрузка и фильтрация базы
      │
      ▼
data/benefits.json статичная демо-база (21 запись)
```

Один контейнер, один процесс, без базы данных и внешних сервисов, кроме
самого MAX. Состояние диалога нигде не хранится: каждый шаг закодирован в
payload кнопки (`CategoryPayload` → `RegionPayload` → `DetailPayload`),
поэтому перезапуск бота не обрывает открытые у пользователей диалоги.
Кнопки, отправленные до появления полей `category` и `region` в
`DetailPayload`, тоже продолжают работать (`LegacyDetailPayload`).

Как бот переживает сбои: ошибки внутри хэндлеров логируются и не обрывают
цикл long polling; при временном сбое сети или MAX (таймаут, ответы 5xx и
429) запуск повторяется до 5 раз, при неверном или пропущенном токене бот
сразу завершается с понятным сообщением в логе; если исходное сообщение с
кнопкой удалено, ответ уходит пользователю в личные сообщения.

### Файлы

- `data/benefits.json`: база льгот (21 запись, федеральные и примеры по
  6 регионам: Калмыкия, Москва, Краснодарский край, Свердловская область,
  Татарстан, Санкт-Петербург).
  Суммы актуальны на дату сбора (см. `_meta.disclaimer` в файле), перед
  подачей заявления уточняйте условия в органах соцзащиты/СФР/Госуслугах.
- `benefits_data.py`: загрузка базы и фильтрация по категории/региону.
- `benefits_bot.py`: сам диалог, каждый шаг кодируется в payload кнопки
  (`CategoryPayload` → `RegionPayload` → `DetailPayload`), поэтому бот не
  теряет контекст пользователя даже после перезапуска. Ошибки внутри
  хэндлеров логируются и не обрывают long-polling цикл.

### Как расширить базу

Чтобы расширить базу, просто добавьте объект в массив `benefits` в
`data/benefits.json` (поля: `id`, `title`, `category`, `region`, `summary`,
`description`, `source` (нормативный акт и ответственное ведомство,
откуда взята льгота), `how_to_apply`, `documents` (список строк с
перечнем документов для оформления); новая категория/регион добавляется
в `_meta.categories` / `_meta.regions` в том же файле. Каждая карточка
льготы в боте показывает `source` пользователю отдельной строкой
(«📚 Источник»): это не только служебное поле для разработчика.

## Данные и тестовые данные

- **Происхождение:** база собрана вручную и лежит в одном файле,
  `data/benefits.json`. Для каждой записи в поле `source` указан
  нормативный акт и ответственное ведомство, пользователь видит его в
  карточке («📚 Источник»).
- **Актуальность:** дата сбора хранится в `_meta.collected` (12.09.2026) и
  показывается в каждой карточке. Суммы и условия могут меняться, поэтому
  карточка напоминает сверить их с органом соцзащиты, СФР или Госуслугами.
- **Это тестовые данные MVP.** Реальной интеграции с Госуслугами, СФР или
  региональными системами нет, бот не выдаёт свои ответы за решение
  ведомства.
- **Работа с базой:** данные читаются один раз при старте, поэтому после
  правки `data/benefits.json` бота нужно перезапустить (в Docker:
  `docker compose up --build`). Поля записи описаны выше, в разделе «Как
  расширить базу».
- **Персональные данные:** бот их не собирает и не хранит, базы данных у
  него нет. Имя из профиля MAX приходит в самом событии и используется
  только для приветствия. Код бота не пишет в логи ни текст сообщений, ни
  имена. Библиотека `maxapi` выводит в лог технические идентификаторы чата
  и пользователя.

## Внешние сервисы и интеграции

Единственный внешний сервис: MAX Bot API, через библиотеку `maxapi`. Бот использует получение обновлений (long polling),
отправку сообщений, ответ на нажатие кнопки и проверку токена
(`bot.get_me()` при старте). По желанию, если задан `MAX_DELETE_WEBHOOK=1`,
удаляются подписки на вебхук. Госуслуги, СФР и другие ведомственные
системы не подключены. Собственного API у решения нет, поэтому
`openapi.yaml` и `DATA-API.yaml` не требуются.

Зависимости зафиксированы в `requirements.txt` с точными версиями. Все
они распространяются по свободным лицензиям (MIT, BSD, Apache-2.0, PSF).
У `maxapi` поле лицензии на PyPI пустое, лицензия MIT указана в её
репозитории (github.com/love-apples/maxapi).

## Масштабирование

**Ядро продукта, которое не меняется:** проблема («узнать, что положено и
как оформить»), логика сценария (категория → регион → карточка), кнопочный
интерфейс, модель данных (категория, регион, карточка с источником и
документами) и архитектура.

**Переменная часть, которую нужно менять при переходе в новый контекст:**
региональные данные и нормативные акты, набор категорий, источники и даты
актуальности, тексты интерфейса, а в перспективе и подключение реальных
систем вместо статичной базы.

Как это работает на практике: новый регион, новая категория или новая
льгота добавляются записью в `data/benefits.json`, код и архитектура не
меняются. Демо-база уже содержит пять категорий и шесть регионов плюс
федеральный уровень, и это показывает переход из основного сценария
(многодетная семья) в соседние.

**Что потребуется для роста:** владелец данных с понятным процессом
обновления (кто и как часто сверяет суммы и условия), проверка записей по
первоисточникам, для новых регионов вычитка региональных актов, для
большой аудитории проверка нагрузки. Главный риск: устаревшие сведения,
поэтому бот показывает источник и дату в каждой карточке.

**Пилот:** один регион с полностью вычитанной базой мер для многодетных
семей. Предлагаемые метрики: доля пользователей, дошедших до карточки
льготы; число открытых карточек на человека; доля пользователей, которые
после разговора с ботом знают, какие документы собрать (короткий опрос).
Следующий шаг после пилота: соседние регионы и категории.
